# Технологический стек Memory Game

Документ описывает самостоятельный проект `memory-game`. Основание — [официальное задание RS School](https://github.com/rolling-scopes-school/tasks/blob/master/tasks/memory-game/README.md), проверенное 5 октября 2026 года, и фактические файлы проекта. Правила разработки находятся в [AGENTS.md](../AGENTS.md), инструкция запуска — в [README.md](../README.md).

## Что настроено сейчас

| Технология | Назначение и текущее состояние |
| --- | --- |
| HTML | `index.html`: метаданные, подключение CSS и скрипта. В исходном `<body>` только `<script>`. |
| CSS | Подключён `src/styles/style.css`; пока содержит только комментарий. |
| JavaScript без фреймворков | `src/main.js` — будущая точка входа; пока содержит только комментарий. |
| Нативные ES modules | Скрипт подключён с `type="module"`; модульные импорты ещё не добавлены. |
| Статические ресурсы | Каталог `public/assets/images/cards/` подготовлен, изображения ещё не добавлены. |

Интерфейс, игровая логика, модальные окна и сохранение рейтинга пока не реализованы. После запуска ожидается пустая страница.

Внешних зависимостей, `package.json`, lock-файлов и сборщика нет. Пакетный менеджер не выбран. Линтер, форматтер и автоматический тестовый инструмент не настроены. Серверная часть и база данных отсутствуют.

HTML и CSS используются как браузерные стандарты, а не пакеты с зафиксированными версиями. Конкретная версия ECMAScript и минимальные версии браузеров в проекте пока не закреплены; для запуска нужен браузер с поддержкой ES modules.

`localStorage` хранит строковые значения и относится к origin страницы: смена протокола, хоста или порта означает другое хранилище. При реализации нужно проверять прочитанные данные и обрабатывать ошибки доступа или разбора JSON.

Для общей модальной оболочки можно выбрать [HTMLDialogElement](https://developer.mozilla.org/ru/docs/Web/API/HTMLDialogElement) или собственную реализацию на DOM. Решение пока не принято. [Fetch API](https://developer.mozilla.org/ru/docs/Web/API/Fetch_API/Using_Fetch) допускается для отдельного файла данных карточек, но пока не используется.

## Требования задания, влияющие на реализацию

- Поле содержит 16 карточек — 8 пар. Случайное перемешивание выполняется при загрузке и новой игре.
- Ход считается при открытии второй другой доступной карточки независимо от совпадения изображений. Повторные клики игнорируются.
- Несовпавшая пара закрывается через 700–1500 мс; до этого выбор других карточек блокируется. Перезапуск отменяет таймер, просмотр рейтинга — нет.
- Победа и рейтинг используют общую оболочку модального окна. Закрытие: кнопка, фон, Escape; фон и прокрутка блокируются.
- Рейтинг сохраняет один результат после победы и оставляет 10 лучших: меньше ходов выше, при равенстве раньше завершённая игра выше. Дата отображается как `ДД.ММ.ГГГГ`.
- Весь интерфейс создаётся через `document.createElement`, включая модальные окна. Самописные обёртки разрешены.
- Запрещены присваивания `innerHTML`/`outerHTML`, `insertAdjacentHTML`, `document.write`/`writeln`, разбор HTML через `DOMParser`/`Range.createContextualFragment`, `alert`/`confirm`/`prompt` и сторонние библиотеки интерфейса, DOM и игровой логики.

Источник требований — [раздел «Требования к реализации»](https://github.com/rolling-scopes-school/tasks/blob/master/tasks/memory-game/README.md#требования-к-реализации). Дизайн свободный; конкретная сетка, звук и анимации не определяют выбранный стек.

## Организация проекта

| Путь | Ответственность |
| --- | --- |
| `index.html` | Подключение стилей и точки входа |
| `src/main.js` | Запуск приложения и соединение модулей |
| `src/game/` | Состояние, перемешивание, ходы, совпадения и таймеры; без DOM и хранения |
| `src/ui/` | Создание DOM, события, отображение состояния и общая модальная оболочка |

| `src/styles/style.css` | Оформление приложения |

Каталоги модулей и изображений пока содержат только `.gitkeep`. Импорты будущих модулей должны использовать относительные пути с расширением `.js`. Без сборщика `public` остаётся обычным каталогом: путь к изображениям начинается с `./public/assets/images/`.

## Запуск и проверка

Приложение исполняется в браузере. Сборка и установка зависимостей не требуются. Используйте имеющийся статический HTTP-сервер из каталога `memory-game`; открытие через `file://` не подходит для работы ES modules.

Например, если Python уже установлен:

```powershell
python -m http.server 8080
```

Откройте [http://localhost:8080](http://localhost:8080); остановка сервера — `Ctrl+C`. Python здесь лишь необязательный способ раздачи файлов, а не часть стека приложения.

Если Node.js уже установлен, из каталога проекта можно проверить синтаксис точки входа:

```powershell
node --check src/main.js
```

Node.js — вспомогательный инструмент проверки, не среда исполнения игры. Версия Node.js в проекте не закреплена. Эта команда не проверяет DOM и игровое поведение.

После реализации нужны ручные проверки в браузере: быстрые клики, несовпавшая пара, перезапуск во время таймера, победа, закрытие модальных окон и сохранение рейтинга после перезагрузки. Проверять ошибки загрузки и JavaScript следует в инструментах разработчика браузера.

Сборщики, линтеры, форматтеры и тестовые инструменты [разрешены заданием](https://github.com/rolling-scopes-school/tasks/blob/master/tasks/memory-game/README.md#интерфейс-и-инструменты), но пока не выбраны и не установлены. Их добавление требует согласования согласно правилам проекта.
