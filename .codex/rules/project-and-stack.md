# Стек и структура

Источники: [стек](../../docs/TechnologyStack.md), [архитектура](../../docs/Architecture.md), [README](../../README.md), [AGENTS](../../AGENTS.md).

- HTML/CSS/vanilla JS, нативные ES modules и встроенные браузерные API. Не вводи фреймворк, сборщик, сервер или зависимость ради небольшого проекта. Проверяй наличие и версии инструментов, не выдумывай конфигурацию.
- Main соединяет callbacks и модули; game хранит состояние/таймер; UI создаёт DOM и отображает снимок; storage обрабатывает рейтинг; utils содержит действительно общие функции.
- Game/storage не импортируют UI или main; UI получает действия callbacks и не импортирует engine/store. Не определяй игровые правила CSS-классами.
- Создавай модуль вместе с работающей ответственностью, без пустых заготовок/лишних обёрток. Импорты относительные, с .js.
- Public — обычная папка. URLs изображений начинаются с ./public/assets/images/cards/; пути от корня могут сломать деплой в подкаталоге.
- Запуск через имеющийся статический HTTP-сервер из корня проекта, не file://. Python/Node — вспомогательные инструменты, не runtime приложения.
- Документы описывают целевую реализацию; JS/CSS сейчас содержат комментарии. Обновляй сведения о статусе после реализации без переписывания несвязанных документов.
