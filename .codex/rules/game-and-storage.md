# Игра, таймер и рейтинг

Источники: [ТЗ](../../docs/TermsOfReference.md), [контракты](../../docs/Architecture.md).

- Новая партия сразу: 16 уникальных ID, 8 pairId по два экземпляра; перемешивается копия алгоритмом Фишера — Йейтса. Закрытое поле, нулевые ходы/пары.
- Ход — вторая другая доступная карточка независимо от изображения. Повторный ID, открытая/найденная карточка, третья при ожидании и выбор после победы игнорируются.
- Engine — источник состояния; фазы idle/one-open/waiting-mismatch/finished, статусы closed/open/matched. Чистые переходы не обращаются к DOM/storage/времени и не меняют вход; snapshots не дают UI изменять engine.
- Mismatch сразу блокирует выбор, один таймер 1000 мс (таск допускает 700–1500). Restart отменяет таймер, меняет roundId и обнуляет состояние; callback проверяет раунд/фазу. Destroy инвалидирует callbacks.
- Рейтинг не сбрасывает/не приостанавливает игру: таймер закрывает пару под окном в исходный срок. Header доступен при ожидании, пока modal закрыт.
- После восьмой пары completedAt фиксируется один раз. Main помечает handledRoundId до addResult/победы. Окна/restart не добавляют результат повторно, включая сбой записи.
- Только memory-game.leaderboard.v1: JSON-массив { moves, completedAt }. Безопасные целые: moves >= 8, timestamp >= 0 и допустим для Date. Некорректные записи игнорируются, повреждённый JSON/не-массив дают пустой список.
- Сортировка moves, затем completedAt по возрастанию, при равенстве порядок добавления. Топ-10; одинаковые показатели разных партий допустимы. Место индекс + 1, дата ДД.ММ.ГГГГ в timezone браузера; поле не сохраняется.
- Обрабатывай даже отказ доступа к window.localStorage. При ошибке чтения/записи единый список сеанса сохраняется в режиме memory; новые результаты не заменяются старым storage при просмотре. UI получает режим сохранения.
