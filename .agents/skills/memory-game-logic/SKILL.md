# Логика Memory Game

Прочитай [AGENTS](../../../AGENTS.md), [игра/storage](../../../.codex/rules/game-and-storage.md), затронутые контракты [Architecture](../../../docs/Architecture.md) и сценарии [ТЗ](../../../docs/TermsOfReference.md). Документы описывают будущую реализацию, не подтверждают готовность кода.

## Workflow

1. Найди реальные модули/вызовы/конфигурацию: каталоги могут быть пустыми. Создавай нужную ответственность в рамках запроса. Нативные ES modules, относительные .js, без сторонних библиотек.
2. Отдели чистые переходы от engine/таймера. Проверь 16 ID, восемь pairId по два, фазы/счётчики. Ход — вторая другая доступная карточка; match по pairId. Ignored действия не меняют состояние/уведомления; snapshots — копии.
3. Mismatch сразу блокирует выбор, один таймер 1000 мс. Restart сначала clearTimeout, затем новый roundId/состояние; callback проверяет раунд/фазу. Destroy инвалидирует callbacks. Рейтинг не меняет таймер.
4. Storage: v1 ключ, проверка JSON/целых/Date, сортировка moves/completedAt, топ-10. Дата из победы, одинаковые показатели разных партий допустимы. Обработай ошибку доступа к localStorage; при отказе единый список памяти не перезаписывается старым storage.
5. Main помечает roundId обработанным до addResult/победы. Не сохраняй незавершённые игры и из render/закрытия окна; после ошибки запись уже есть в памяти и не добавляется повторно. Передавай UI persistence; не создавай DOM в game/storage.
6. Проверь особенно restart → выбор новой партии → старый callback и storage failure → новый результат → просмотр рейтинга. Применяй доступные проверки, не устанавливай средства без разрешения; сообщи реальные результаты.

При UI-интеграции body только script, document.createElement/textContent; нельзя запись innerHTML/outerHTML, вставка/разбор HTML-строк, alert/confirm/prompt и UI/DOM/игровые библиотеки. UI отображает snapshot и не выводит правила из CSS. Для изменений представления прочитай [UI-правила](../../../.codex/rules/ui-and-design.md).
